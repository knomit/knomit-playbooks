# Mission repo shape: coordination signals and per-task annotations in the mission repo, the knowledge in a target knowledge base, and one fold task as the only writer of shared facts

The `mission` template (`kb/templates/mission/`) is built from knomit's generic primitives only: an ontology with validations and triggers, trigger scripts, skills and a recipe.

**Two repos.**
- The MISSION repo holds coordination signals (tasks, claims, queues, acknowledgements; `kind: pragmatic`, `type: signal`, `learn_dedup: off`) and one topic of annotations, `annotations/<task-id>/`.
- The TARGET knowledge base, named in the mission's charter, holds what the agents learn (findings, syntheses, hypotheses) as ordinary facts under its own topics. It exists before the mission and stays after it, so each fact's history continues there. Nothing in it refs the mission repo.

**Annotations.** A fact about a target fact: its ref is `kb://<target repo id>/<path>`, its `context` says what it is (`kind: verdict`, `verdict`, `confidence`), declared in the mission ontology (`kb/howto/ontology/declare-context/`). Each task writes into its own folder, so parallel tasks never write one file. Find one task's verdicts with `path: "kb/annotations/<task-id>/"` and `context: {"kind": "verdict"}`.

**One writer per shared fact.** Two tasks that update the same fact in parallel cannot both land as written: the second experiment commit is refused or field-merged. So cross-check tasks never update what they check; each writes one annotation per checked fact. One fold task, assigned to one agent after every cross-check has acknowledged, reads the annotations and updates, merges or retracts the hypotheses in one experiment on the target knowledge base. A cross-check lists the exact paths to check (`check: <path>`), picked by the coordinator from git authorship, so no checker checks its own facts.

**Two ways to take a task.**
- Claim / wait / take: every machine with capacity claims; at the claim's `expires` each ranks the live claims the same way and the winner takes with one atomic move (write the working copy, retract the task and its claims). A heuristic plus a backstop (`dup-check`), never exclusion.
- Host-awarded: machines bid; the awarder alone awards with one atomic move that deletes the offer, so each offer is awarded exactly once. Needs the awarder up.
A task assigned to one agent goes straight into its queue and is never claimed.
