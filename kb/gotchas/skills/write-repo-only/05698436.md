# A binding serves the skills of its write repo only: a lens serves none of its read members' skills, and a subscription cannot be a lens's write repo, so bind a subscribed repo directly to get its skills

knomit answers `knomit_skill` and the MCP prompt list from ONE repo: the binding's write repo.

- **Bound to a repo**: that repo's skills. A subscription has no agent branch, and still serves its skills.
- **Bound to a lens**: the skills of the lens's write repo only. Repos mounted read-only in the lens serve no skills there, though their facts are queried.
- **A subscription cannot be a lens's write repo** (knomit refuses it: `lens write repo is a subscription`). So a subscribed repo's skills reach an agent only on a binding of that repo itself.
- **The unscoped endpoint** lists no prompts; there, call `knomit_skill` with a binding handle.
- **`kb --repo <subscription>` does not start**: the bridge asks the server for the repo's agent branch, and a subscription has none ("server did not return agent_branch"). Reach a subscription through the unscoped endpoint and `knomit_bind`, or connect an MCP client to the repo's own endpoint, `/api/v1/repos/<name>/branches/<branch>/mcp` (a `/` in the branch name written as `:`), which serves its prompts and `knomit_skill` without a binding.

For `knomit-playbooks` on the unscoped endpoint:

```json knomit_bind
{"repo": "knomit-playbooks"}
```

```json knomit_skill
{"binding": "<handle>", "name": "program-knomit"}
```
