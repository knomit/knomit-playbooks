# knomit_query's path is a plain string prefix of the stored path: include the kb/ root and end it with /, or kb/howto/trigger also matches kb/howto/triggers-inline/

`path` is matched as `stored_path LIKE '<path>%'`, with no notion of folders.

- **Include the ontology root.** Stored paths start with the repo's ontology root, `kb/` by default. `path: "howto/"` matches nothing; use `path: "kb/howto/"`.
- **End it with `/`.** `path: "kb/annotations/task-1"` also returns `kb/annotations/task-12/…`. `path: "kb/annotations/task-1/"` returns only that folder.
- **`_` and `%` are wildcards.** They are not escaped: `_` matches any one character and `%` any run, so `path: "kb/a_b/"` also matches `kb/axb/`. A folder name with `_` can return a sibling folder's facts; check the `file` of each row.
- A path with a segment beginning with a dot (`.knomit/`) is refused; `artifacts/` returns nothing. Both are read by exact path with `knomit_explain`.
- Through a lens, `path: "kb/howto/"` searches only the mounts whose ontology has the topic `howto`. A `kb://<repo-id>/kb/…` path searches that one mount.
