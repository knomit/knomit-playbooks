# A repo's ontology is set when knomit creates it, by the create mode: template, initialize, custom and preset write it; clone and subscribe take the remote's and refuse template, ontology_preset and ontology_yaml; a fleet-id ontology is never created as a local repo

- `template` (a local create) and `initialize` with `template` write the template's root `README.md` and `.knomit/**`, read at the source repo's consensus tip, in one signed commit on the agent branch. The template's ontology is parsed as a NEW ontology; a template that fails is refused before anything is written.
- `initialize` takes exactly one of `template`, `ontology_preset` and `ontology_yaml` and writes it onto knomit's agent branch, cut from the remote branch's tip; the branch's other files stay, and template files replace files at the same paths on the agent branch only. The remote branch needs a commit and no ontology; the remote's consensus branch is never written.
- `clone` and `subscribe` take the ontology from the remote branch's `.knomit/ontology.yaml`. A request that also names `template`, `ontology_preset` or `ontology_yaml` is refused.
- `custom` writes the ontology parsed from the `ontology_yaml` you pass, re-serialized: comments and formatting are dropped. It writes nothing else, so a template's skills, recipes and trigger scripts need `template` (or `initialize` with `template`). It parses the YAML as a NEW ontology: problems that an existing repo only warns about (an attribute in the wrong scope, a bad repository-level value, a bad guidance value) are refused. Validate first with `POST /api/v1/ontologies:validate`.
- `preset` takes the copy embedded in the running knomit binary (`default`, `code` or `fleet`), which can differ from a template copied at another knomit commit.
- Never create a repo with the ontology id `fleet` as a local repo (the `fleet` preset, the `fleet` template in mode `template` (refused, 409) or the `fleet` template as `ontology_yaml`): knomit treats any mounted repo with that id as the instance's fleet, and `knomit fleet register <url>` for the real fleet then fails with `already_registered`. Create the fleet repo with `initialize` and the `fleet` template on a git host, and join with `knomit fleet register` once a person has merged the creating instance's agent branch into the host's main.
- A repo opens without accepting writes when its ontology is missing or does not parse; knomit never substitutes a default.

How to create: `kb/howto/templates/create-repo/`.
