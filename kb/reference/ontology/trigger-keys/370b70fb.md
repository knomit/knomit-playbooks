# Trigger keys: name, match, on (learn, update, retract, due), if, do (emit, script, push, run), script, js, recipe - an unknown key makes the trigger invalid

Every key a `triggers:` entry may carry, as knomit's ontology schema defines it:

| key | value |
|---|---|
| `name` | Unique in the ontology, kebab-case. The trigger's bookmark is keyed by it: renaming starts it fresh. |
| `match` | Path pattern relative to the ontology root, starting with the topic's path. `*` one segment, `**` any depth, `?` one character; `{agent}`, `{host}`, `{fp8}` are this instance's. Absent: everything under the topic. Never a dot path. |
| `on` | `learn`, `update`, `retract`, `due`: one value or a list. `due` fires once per trigger when a matching fact's `expires` has passed (facts at the head only); changing the fact's `expires` re-arms it. |
| `if` | Optional JavaScript condition over `fact`, `agent` and `change`. Empty means always. |
| `do` | `emit`: a log line and an SSE event. `script`: run the inline `js` code or `.knomit/triggers/<script>.js` in the sandbox with the host API (`query`, `explain`, `learn`, `update`, `retract`, `emit`, `push`, `run`). `push`: ask this machine's sync loop for a round now (a 1 s countdown batches a burst). `run`: start the recipe named by `recipe`, without waiting. |
| `script` | For `do: script`: the kebab-case name of `.knomit/triggers/<name>.js`. Exactly one of `script` and `js`. |
| `js` | For `do: script`: the code inline (a YAML block scalar for several lines). Compiled with the ontology and cached by its source hash. |
| `recipe` | For `do: run`: the kebab-case recipe name (`kb/howto/recipes/write-recipe/`). |

Required: `name`, `on` and `do`; for `do: script`, exactly one of `script` and `js`; for `do: run`, `recipe`. A missing required key, a key not in this table, or a value knomit does not know makes the trigger `invalid`; the rest of the ontology still loads. How to write one: `kb/howto/triggers/write-trigger/`.
