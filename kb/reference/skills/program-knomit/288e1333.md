# program-knomit skill: how an agent answers "set up X in knomit" from this knowledge base: read it through MCP only (bind, query by topic, find a template, read its files with knomit_explain), then create the repo through REST or the web UI

File: `.knomit/skills/program-knomit/SKILL.md`. knomit serves it on a binding of `knomit-playbooks` itself: `knomit_skill` with name `program-knomit`, or the `program-knomit` prompt on the repo's own MCP endpoint.

```json knomit_skill
{"binding": "<handle>", "name": "program-knomit"}
```

Its steps:
1. Bind `knomit-playbooks` (on its own endpoint the binding comes from the URL). Write nothing to it unless you were asked to add to it.
2. Find what applies: `knomit_query` by topic (`kb/howto/`, `kb/patterns/`, `kb/reference/`, `kb/gotchas/`, `kb/templates/`), each `path` ending in `/`; read each fact you rely on with `knomit_explain`.
3. Pick a template: `knomit_query` with `path: "kb/templates/"` and `context: {"part": "template"}`.
4. Read the template and its files: explain the template fact; its walk holds the file facts, the edit facts and a `system_file` node per file. Explain a node's `path` and `commit` for the file's raw `content`. A file at `.knomit/templates/<name>/<path>` lands at `<path>` in the new repo.
5. Create the knomit repo, through REST (`POST /api/v1/repos`) or the web UI: `mode: custom` with the ontology inline for an ontology-only template, `mode: clone` of a pushed git repository for `mission`, `knomit fleet register` for a fleet.
6. Check: `kb/gotchas/`, `POST /api/v1/ontologies:validate`.
