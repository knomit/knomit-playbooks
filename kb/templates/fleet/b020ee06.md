# The fleet template: the fleet repository, one member record per agent under kb/members/<agent-id>/, knomit's built-in fleet preset (ontology id fleet); created in mode initialize and joined with knomit fleet register, never created as a local repo

Template folder: `.knomit/templates/fleet/`.

**What it is for.** The fleet repository, the source of truth for a knomit fleet. Its ontology is knomit's embedded `fleet` preset: one topic, `members`, one member record per agent, never deleted.

**Its files** (one fact each under `kb/templates/fleet/files/`): `README.md` and `.knomit/ontology.yaml`, landing at the same paths in the new repo.

**What to edit** (under `kb/templates/fleet/use/`): keep the id `fleet`; hosting and who accepts members; the README.

**How to create a repo from it.** Create it in mode `initialize`, never `template`: knomit refuses the fleet template in mode `template` (409), because it treats any local repo with the id `fleet` as the instance's fleet. Give `initialize` a git repository every instance of the fleet can reach, whose branch has a commit and no knomit ontology:

```
POST /api/v1/repos
{"name": "<fleet repo>", "mode": "initialize", "origin": {"url": "<git URL>", "branch": "main"}, "template": {"repo": "knomit-playbooks", "name": "fleet"}}
```

Once a person merges the creating instance's agent branch into main, each instance joins with `knomit fleet register <url>` (REST `PUT /api/v1/fleet {"url": "<url>"}`), which writes its member record on its agent branch; a person accepts it by merging that branch into main.
