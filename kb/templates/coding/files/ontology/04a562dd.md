# coding .knomit/ontology.yaml: knomit's embedded code preset byte for byte (id source-code), eight topics; principles carries four validations; lands at .knomit/ontology.yaml

File: `.knomit/templates/coding/.knomit/ontology.yaml`. Lands at `.knomit/ontology.yaml` in the new repo.

Byte for byte knomit's embedded `code` preset, `internal/fact/ontology_code.yaml` (id `source-code`). Its topics are invariants, architecture, conventions, decisions, gotchas, incidents, meta and principles, each with child categories.

`principles` carries four validations: a fact there is refused unless its entities include `designer`, it is `kind: pragmatic` and `type: policy`, its domain is non-empty, and its domain is not `global` together with other values. The other topics carry none. No triggers, context, skills or recipes.

It is the template's only file under `.knomit/`, so a repo created from the template holds this ontology and the README. With the id `source-code`, knomit upgrades a stored ontology that is a strict subset of a newer embedded preset when the repo opens.
