# The coding template: a knowledge base for one codebase, knomit's built-in source-code preset (ontology id source-code) with invariants, architecture, conventions, decisions, gotchas, incidents, meta and principles topics, ontology only

Template folder: `.knomit/templates/coding/`.

**What it is for.** A knowledge base for one codebase. Its ontology is knomit's embedded `code` preset (id `source-code`): the topics invariants, architecture, conventions, decisions, gotchas, incidents, meta and principles. `principles` is validated (`kind: pragmatic`, `type: policy`, entity `designer`, a valid domain); no triggers, skills or recipes.

**Its files** (one fact each under `kb/templates/coding/files/`): `README.md` and `.knomit/ontology.yaml`, landing at the same paths in the new repo.

**What to edit** (under `kb/templates/coding/use/`): the taxonomy (or nothing, to keep the preset and its upgrades), and the README, which names the codebase.

**How to create a repo from it.** It is an ontology only. Create a repo from the template: `POST /api/v1/repos` with mode `template`, `kb repo create <new repo> --template knomit-playbooks/coding`, or the web UI wizard's **From a template**. knomit copies `README.md` and `.knomit/ontology.yaml` to the same paths in the new repo, in one signed commit, and the new repo is an ordinary repo afterwards (`kb/howto/templates/create-repo/`).

```
POST /api/v1/repos
{"name": "<new repo>", "mode": "template", "template": {"repo": "knomit-playbooks", "name": "coding"}}
```
