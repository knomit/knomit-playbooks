# The mission template creates a mission repo: coordination signals for one mission, plus annotations on a target knowledge base; seven files, created by cloning a git repository that holds them

Template folder: `.knomit/templates/mission/`.

**What it is for.** The agents of one mission coordinate in the mission repo: tasks, claims, per-agent queues (`inbox/<agent-id>/working/` and `active/`), acknowledgements, and the offers, bids and awards of the host-awarded pattern. Every coordination topic holds signals (`kind: pragmatic`, `type: signal`) with `learn_dedup: off`. One more topic, `annotations/<task-id>/`, holds facts ABOUT the target knowledge base's facts, typed by a declared `context` (`kind: verdict`). The knowledge the agents produce goes to the target knowledge base the mission's charter names, as ordinary facts. The shape and its reasons: `kb/patterns/missions/repo-shape/`.

**Its files** (one fact each under `kb/templates/mission/files/`; each lands at the path after `.knomit/templates/mission/`):
- `README.md`: how the mission repo works. Read it before you edit anything.
- `.knomit/ontology.yaml`: the topics, validations, repo settings and every trigger.
- `.knomit/triggers/claims.js`: pattern 1, claim / wait / take.
- `.knomit/triggers/awards.js`: pattern 2, host-awarded.
- `.knomit/skills/post-task/SKILL.md` and `.knomit/skills/work-task/SKILL.md`: how a session posts a task and how it drains its queue.
- `.knomit/recipes/work-task.js`: the recipe that starts one headless Claude Code session to drain the queue.

**What to edit after creating it from the template** (one fact each under `kb/templates/mission/use/`): hosting, timing, capacity and lease, the session, the skills, the target knowledge base, the take pattern.

**How to create a repo from it.** It has triggers, skills and a recipe, so write all seven files to their paths in a new git repository, push it, and create the knomit repo by cloning it (`kb/howto/templates/create-repo/`):

```
POST /api/v1/repos
{"name": "<mission repo>", "mode": "clone", "origin": {"url": "<git URL>", "branch": "main"}}
```

A local create with `ontology_yaml` carries the ontology only. A pushed repository that holds the other six files but no ontology can be created with `mode: initialize` instead. Then host it as the README's "Knomit-hosted" or "GitHub-hosted" section says.
