# The mission template: the coordination repo for the agents of one mission, with signals for tasks, claims, queues and acknowledgements plus annotations on a target knowledge base; seven files

Template folder: `.knomit/templates/mission/`.

**What it is for.** The agents of one mission coordinate in the mission repo: tasks, claims, per-agent queues (`inbox/<agent-id>/working/` and `active/`), acknowledgements, and the offers, bids and awards of the host-awarded pattern. Every coordination topic holds signals (`kind: pragmatic`, `type: signal`) with `learn_dedup: off`. One more topic, `annotations/<task-id>/`, holds facts ABOUT the target knowledge base's facts, typed by a declared `context` (`kind: verdict`). The knowledge the agents produce goes to the target knowledge base the mission's charter names, as ordinary facts. The shape and its reasons: `kb/patterns/missions/repo-shape/`.

**Its files** (one fact each under `kb/templates/mission/files/`; each lands at the path after `.knomit/templates/mission/`):
- `README.md`: how the mission repo works. Read it before you edit anything.
- `.knomit/ontology.yaml`: the topics, validations, repo settings and every trigger.
- `.knomit/triggers/claims.js`: pattern 1, claim / wait / take.
- `.knomit/triggers/awards.js`: pattern 2, host-awarded.
- `.knomit/skills/post-task/SKILL.md` and `.knomit/skills/work-task/SKILL.md`: how a session posts a task and how it drains its queue.
- `.knomit/recipes/work-task.js`: the recipe that starts one headless Claude Code session to drain the queue.

**What to edit** (before the create, through the edited-copy route in `kb/howto/templates/create-repo/`; one fact each under `kb/templates/mission/use/`): hosting, timing, capacity and lease, the session, the skills, the target knowledge base, the take pattern.

**How to create a repo from it.** Create a repo from the template: `POST /api/v1/repos` with mode `template`, `kb repo create <mission repo> --template knomit-playbooks/mission`, or the web UI wizard's **From a template**. knomit copies the template's `README.md` and everything under `.knomit/` (all seven files) to the same paths in the new repo, in one signed commit (`kb/howto/templates/create-repo/`):

```
POST /api/v1/repos
{"name": "<mission repo>", "mode": "template", "template": {"repo": "knomit-playbooks", "name": "mission"}}
```

For a mission repo on GitHub or another forge, use mode `initialize` with the forge repository as `origin` and the same `template`. With edits: write the seven files with your edits to a git repository, push it, and create with mode `clone`; for a knomit-hosted repo remove the origin afterwards. Then host it as the README's "Knomit-hosted" or "GitHub-hosted" section says.
