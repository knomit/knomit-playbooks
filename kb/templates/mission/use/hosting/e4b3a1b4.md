# Mission edit, hosting: keep consensus: auto for a repo a knomit instance hosts; drop that line for a repo on GitHub or another forge, and keep conflicts as it is

The settings are in `.knomit/ontology.yaml` (`attributes`) of the new repo.

- **Hosted by a knomit instance** (the template's default): keep `consensus: auto`. Create the repo from the template on the hosting instance (mode `template`); it has no origin, so that instance owns the consensus branch and merges every branch a peer pushes. The other instances clone the repo from the host.
- **On GitHub or another forge**: create the repo from the template in mode `initialize` with the forge repository as `origin`, then delete the `consensus: auto` line. The forge owns the consensus branch, and something there merges the agents' branches into it. Keep `conflicts` exactly as it is.
- `sync: {push: realtime, pull: realtime}` against a forge costs requests: about one fetch every 3 s per participant. On a forge, keep the fleet small, or drop `sync`, and redo the timing rule (`use/timing`).

Set these once, when the repo is created; every instance reads them at the tip of the consensus branch. README sections "Knomit-hosted", "GitHub-hosted" and "Set it once and forget".
