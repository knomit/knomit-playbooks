# Mission edit, timing: WINDOW_SECONDS in claims.js is the claim window X and must satisfy X >= 1.5 x (2N + 2 s), N the largest sync round interval of any participant; 15 s fits the 3 s realtime default

Edit `WINDOW_SECONDS` in `.knomit/triggers/claims.js` whenever the sync inputs change.

X (`WINDOW_SECONDS`) must cover a claim's travel to every decider: the largest sync round interval N of any participant, plus the push countdown (1 s), plus the host's merge and fast-forward (about 1 s), plus one due tick (up to N), with a margin. The template's rule is X ≥ 1.5 × (2N + 2 s).

- With `sync: {push: realtime, pull: realtime}` and the default `[git].realtime_pull_interval` of 3 s, the floor is about 8 s and the template sets X = 15 s.
- A participant with a longer `realtime_pull_interval` raises N for everyone.
- A participant whose knomit does not support `sync` rounds every 300 s: X ≥ about 360 s.
- On a forge, add the time the forge takes to merge an agent branch.
- A host with `[git].local_reconcile_interval = 0` runs no local rounds; keep it above 0.

The dead-winner threshold is 2X. README section "The timing rule".
