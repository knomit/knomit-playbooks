# Mission edit, the target knowledge base: the mission's charter names an existing knowledge base, and each task names it in its body as knowledge base: repo <name> or lens <name>; the knowledge goes there, not into the mission repo

Pick the knowledge base the mission writes its knowledge to: any existing knomit repo or lens, made from any template (`general`, `coding` or another). Name it in the mission's charter, and in each task body as a line `knowledge base: repo <name>` or `knowledge base: lens <name>` (the `post-task` skill writes it).

The session binds it as a second handle and writes findings, syntheses and hypotheses there as ordinary facts, inside one experiment per task. The mission repo holds only signals and `annotations/<task-id>/`, whose refs name target facts as `kb://<target repo id>/<path>`. Nothing in the target knowledge base refs the mission repo.
