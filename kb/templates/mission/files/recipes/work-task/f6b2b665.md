# mission work-task.js: the recipe the wake and lease triggers run, one headless Claude Code session with the unbound kb bridge as its only MCP server; MAX_BUDGET_USD, MODEL and the concurrent/timeout_ms header are the knobs; lands at .knomit/recipes/work-task.js

File: `.knomit/templates/mission/.knomit/recipes/work-task.js`. Lands at `.knomit/recipes/work-task.js` in the new repo.

The recipe the ontology's `wake` and `lease` triggers run (`do: run`, `recipe: work-task`). When this machine's queue `inbox/<agent>/working/` holds a copy, it starts one headless Claude Code session:
- in a fresh temporary folder (`mktemp -d`), removed afterwards;
- with one MCP server, knomit's bridge `kb` unbound (no `--repo`, no `--lens`), and `--strict-mcp-config`;
- with the allowed tools `mcp__<KEY>`, `WebFetch` and `WebSearch`, and `--max-budget-usd`;
- with a prompt that says to bind the mission repo and follow the `work-task` skill, carrying the mission repo's name, the copy's path, its experiment name, the session's lease and the trace as one JSON literal.

**Knobs:**
- The header on the first line, `// knomit: {"concurrent": 1, "timeout_ms": 1800000}`: sessions at once on this machine, and one session's time limit.
- `TIMEOUT_MS = 1800000`: keep it equal to `timeout_ms`.
- `MAX_BUDGET_USD = "5"`: the most one session may spend.
- `MODEL = "sonnet"`, `KEY = "knomit"`.
- The `claude` argv, for another harness.

knomit reads a recipe at the tip of the repo's consensus branch.
