# mission .knomit/ontology.yaml: id mission; signal topics tasks, claims, inbox, acks, offers, bids, awards with learn_dedup off, the annotations topic with context, the frames topic (type frame, learn_dedup off), consensus/conflicts/sync and every trigger; lands at .knomit/ontology.yaml

File: `.knomit/templates/mission/.knomit/ontology.yaml`. Lands at `.knomit/ontology.yaml` in the new repo.

- **Id** `mission`.
- **Repo settings** (`attributes`): `consensus: auto`, `conflicts: {facts: merge, state: consensus}`, `sync: {push: realtime, pull: realtime}`.
- **Signal topics**: `tasks`, `claims`, `inbox`, `acks`, `offers`, `bids`, `awards`. Each has `learn_dedup: off` and a validation that refuses anything but `type: signal`. `tasks` and `offers` also require exactly one entity (the task id) and `expires`; `claims` and `inbox` require `expires`.
- **`annotations`**: `learn_dedup: off` and the context keys `kind` (enum `[verdict]`, required), `verdict` (enum `[corroborate, contradict]`) and `confidence` (number, 0 to 1).
- **`frames`**: a mission's thinking-process nodes (`kind: pragmatic`, `type: frame`). Two settings, both in the topic: `learn_dedup: off`; one validation (`fact.type === 'frame'`) that refuses anything else under `frames/`. There is no `status` context key and no other context key. A frame's parents are the frames it refs (any ref whose target is a frame), and a frame may have several; the template does not require a frame to have a parent. There is no trigger.
  - Frames are never deduplicated, merged or used to settle a hypothesis because of the topic's `learn_dedup: off`, NOT because of the `frame` type: the type alone does not prevent it. A frame written to a topic that lacks `learn_dedup: off` can be merged with a sibling, absorb an observation, or settle a nearby hypothesis.
  - A frame can be written only from a knomit build that has the `frame` type (knomit PR 668) and pins this template (knomit PR 669); an older build refuses the type.
  - A frame has no status because nothing reads one: an abandoned frame is a retracted frame (user ruling of 2026-10-28; the template change is knomit-playbooks PR #11).
- **Triggers**:
  - `tasks`: `expire` (on due, inline `knomit.retract`), `offer` (on learn, script `claims`);
  - `claims`: `decide` (on due of `claims/*/{agent}/**`, script `claims`);
  - `inbox`: `dup-check` (on learn, script `claims`), `wake` (on learn of `inbox/{agent}/working/**`, recipe `work-task`), `lease` (on due of `inbox/{agent}/**`, recipe `work-task`);
  - `offers`: `expire-offer` (on due, inline), `bid` (on learn, script `awards`);
  - `bids`: `award` (on learn of `bids/{agent}/**`, script `awards`), `withdraw-bid` (on due, inline);
  - `awards`: `take-award` (on learn of `awards/{agent}/**`, script `awards`).

Edits to this file: hosting (`consensus`), the take pattern you keep, the annotation kinds. A repo's ontology is set when knomit creates the repo, so make them before you create it, in the edited copy you create the repo from (`kb/howto/templates/create-repo/`).
