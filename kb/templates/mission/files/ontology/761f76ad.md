# mission .knomit/ontology.yaml: id mission; signal topics tasks, claims, inbox, acks, offers, bids, awards with learn_dedup off, the annotations topic with context, consensus/conflicts/sync and every trigger; lands at .knomit/ontology.yaml

File: `.knomit/templates/mission/.knomit/ontology.yaml`. Lands at `.knomit/ontology.yaml` in the new repo.

- **Id** `mission`.
- **Repo settings** (`attributes`): `consensus: auto`, `conflicts: {facts: merge, state: consensus}`, `sync: {push: realtime, pull: realtime}`.
- **Signal topics**: `tasks`, `claims`, `inbox`, `acks`, `offers`, `bids`, `awards`. Each has `learn_dedup: off` and a validation that refuses anything but `type: signal`. `tasks` and `offers` also require exactly one entity (the task id) and `expires`; `claims` and `inbox` require `expires`.
- **`annotations`**: `learn_dedup: off` and the context keys `kind` (enum `[verdict]`, required), `verdict` (enum `[corroborate, contradict]`) and `confidence` (number, 0 to 1).
- **Triggers**:
  - `tasks`: `expire` (on due, inline `knomit.retract`), `offer` (on learn, script `claims`);
  - `claims`: `decide` (on due of `claims/*/{agent}/**`, script `claims`);
  - `inbox`: `dup-check` (on learn, script `claims`), `wake` (on learn of `inbox/{agent}/working/**`, recipe `work-task`), `lease` (on due of `inbox/{agent}/**`, recipe `work-task`);
  - `offers`: `expire-offer` (on due, inline), `bid` (on learn, script `awards`);
  - `bids`: `award` (on learn of `bids/{agent}/**`, script `awards`), `withdraw-bid` (on due, inline);
  - `awards`: `take-award` (on learn of `awards/{agent}/**`, script `awards`).

Edits to this file: hosting (`consensus`), the take pattern you keep, the annotation kinds. A repo's ontology is set when knomit creates the repo, so make them before you create it.
