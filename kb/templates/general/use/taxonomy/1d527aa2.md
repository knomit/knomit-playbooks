# General edit, the taxonomy: keep the ontology as it is to get the general preset and its upgrades; to build your own taxonomy, change the topics AND the id, name and description

Edit `.knomit/ontology.yaml` before you create the repo, or not at all. Mode `template` copies it as it is; to create with your edit, use `mode: custom` with the edited file as `ontology_yaml`.

- **Keep it as it is** to get the general preset. With the id `general`, knomit treats the repo like one created from the built-in preset: when the stored ontology is a strict subset of a newer embedded preset, knomit upgrades it when the repo opens.
- **Change the topics** to build your own taxonomy, and then also change `id`, `name` and `description` at the top of the file. knomit leaves an ontology that is no longer a subset of its preset alone, with a warning.

A repo's ontology is set when knomit creates it. Validate the edited file with `POST /api/v1/ontologies:validate`.
