# Write a trigger: a triggers: entry on an ontology topic with name, on, match, an optional if, and do (emit, script, push or run); script code goes inline under js: or in .knomit/triggers/<name>.js

A trigger says: when a fact whose path matches `match` is learned, updated, retracted or comes due under this topic, and `if` holds, do `do`. Declare it on the topic in `.knomit/ontology.yaml`. Every key is listed in `kb/reference/ontology/trigger-keys/`.

**Inline script** (one line, from the mission template):

```yaml
topics:
  tasks:
    triggers:
      - name: expire
        on: due
        match: "tasks/**"
        do: script
        js: "knomit.retract(change.path)"
```

**Script file**: `script: claims` runs `.knomit/triggers/claims.js`. Use `js: |` for a few lines and a file for more. A trigger has exactly one of `script` and `js`.

```yaml
      - name: offer
        on: learn
        match: "tasks/**"
        do: script
        script: claims
```

**Start a recipe**: `do: run` with `recipe: <name>` (`kb/howto/recipes/write-recipe/`).

**Rules.**
- `match` is relative to the ontology root and starts with the topic's path: `*` one segment, `**` any depth, `?` one character. `{agent}`, `{host}` and `{fp8}` stand for this instance's values, so `claims/*/{agent}/**` fires on this machine's own claims only.
- `on: due` fires once when a matching fact's `expires` has passed. knomit itself never acts on `expires`: expiry is a trigger like the one above.
- A script runs in a sandbox with the host object `knomit` (`query`, `explain`, `learn`, `update`, `retract`, `emit`, `push`, `run`) and the globals `fact`, `agent` and `change`. Its writes are this machine's commits on its agent branch, stamped `Knomit-Trace`, `Knomit-Cause` and `Knomit-Trigger`. It may not write under `.knomit/`.
- A script file is read at the head of this machine's agent branch; an inline script is part of the ontology.
- A problem in a trigger never breaks the ontology: the trigger is recorded as `invalid` with its error, and its bookmark holds until it is fixed. Inline code that does not compile makes the trigger `invalid`.
- A new trigger starts at the head it first appears at; it does not fire for facts that were already there.
