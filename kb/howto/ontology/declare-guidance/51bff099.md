# Declare guidance for the hypothesize and review prompts with a guidance: block naming files under .knomit/guidance/; knomit reads them at the consensus tip and adds them to those prompts

Guidance is repository policy for knomit's synthesis prompts (`knomit_hypothesize` and `knomit_review`). The ontology names files; the text lives in the files.

```yaml
guidance:                                   # root: applies to every topic
  hypothesize: guidance/all-hypothesize.md
topics:
  forecast:
    guidance:
      hypothesize: guidance/forecast-hypothesize.md
      review: guidance/forecast-review.md
```

- Keys: `hypothesize` and `review`.
- A value is a path relative to `.knomit/`, under `guidance/`, written clean (no `./`, `//`, `..`, leading `/` or trailing `/`), at most 256 bytes. `guidance/x.md` names `.knomit/guidance/x.md`. Inline text is refused: the ontology holds paths only.
- A guidance file must be a regular UTF-8 text file of at most 16 KiB; any other file is skipped with a warning. The guidance section of one prompt is also capped at 16 KiB, cut at a line and marked truncated.
- For a fact's topic, the root block's file comes first, then the nearest declaration on the topic's walk.
- A bad value resolves to NO file for that key at that node; it does not fall back to the parent's file. On an existing repo it is a warning; in a new ontology it is refused.
- knomit reads the ontology and the files at the tip of the consensus branch, at one commit. An edit on an agent branch or in an experiment does not change the prompts until it is merged.
- Nothing from a fact, a task, a context value or a tool argument is substituted into the text.

Commit the guidance files and the ontology through git: `.knomit/` is closed to every fact-tool write.
