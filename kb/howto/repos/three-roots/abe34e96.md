# A knomit repo has three roots: kb/ for facts (fact tools), .knomit/ for the system (written through git only, read by exact path with knomit_explain), artifacts/ for agents' untyped files (knomit_learn path, never indexed)

| root | holds | who writes | seen by |
|---|---|---|---|
| `kb/` (the ontology root) | facts, `kb/<topic>/<category>/<id>.md` | agents, through `knomit_learn`, `knomit_update`, `knomit_retract` | the index, `knomit_query`, `knomit_changes`, triggers, export |
| `.knomit/` | the system: `ontology.yaml`, `triggers/`, `recipes/`, `skills/`, `guidance/` | people, through git (commit, push, merge), and knomit's own code (repo create, preset upgrade) | knomit, which reads known files by name; `knomit_explain` and the REST fact GET by exact path; a fact's ref |
| `artifacts/` | agents' working files that are not knowledge, such as a job's bookkeeping | agents, through `knomit_learn` with `path: "artifacts/<area>/<name>.md"` | only by exact path, with `knomit_explain`; never indexed, queried, exported or seen by a trigger |

**Rules.**
- `.knomit/` is closed to every fact-tool write (`knomit_learn` `path` and `retract`, `knomit_update`, `knomit_retract`, REST PUT and DELETE, experiment resolutions). To change the ontology, a skill, a recipe or a trigger script, commit it through git.
- A file under `.knomit/` is open to reads by its exact path, case kept: `knomit_explain` with `file: ".knomit/<path>"` returns one `system_file` node with its raw `content`, and REST `GET .../facts/.knomit/<path>` on a branch or commit route returns the file. It is never indexed, queried or listed.
- A fact may ref a file under `.knomit/` of its own repo as `.knomit/<path>`. The file must exist at the tip of the branch the write lands on, or the whole write is refused. In the fact's `knomit_explain` walk the file is a `system_file` node pinned at the fact's commit.
- Every other path with a segment beginning with a dot (`.github/`, `kb/.drafts/`) stays closed to the fact tools, for reads and writes.
- An artifact path is at least one folder deep under `artifacts/`, with no empty segment, no segment starting with a dot, and no `..`. `knomit_learn` with `path` cannot be combined with `topic`/`category` or `context`, and fails if the path exists: use `knomit_update` for a new revision.
- `knomit_query` refuses a dot path and returns nothing for `artifacts/`.
- `ontology_root` cannot be `artifacts` or a folder under it.
