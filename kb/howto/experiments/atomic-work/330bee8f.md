# Do multi-fact work atomically: knomit_experiment open forks exp/<name> and moves the session onto it, commit lands it on the agent branch in one step (a merge or a fast-forward), rollback discards it; knomit_learn's retract makes one-commit moves

**An experiment** is an isolated branch for one piece of work.

```json knomit_experiment
{"binding": "<handle>", "action": "open", "name": "gather-q3", "description": "what this is for"}
```

- `open` forks `exp/<name>` from the agent branch and moves this session onto it: every later learn, update, retract, query and review reads and writes the experiment.
- `commit` lands it on the agent branch in one step and deletes it: one merge commit, or a fast-forward with no new commit when the agent branch has not moved since the fork. Either way all of the experiment lands or none of it. If both sides changed a path, the repo's `conflicts` setting settles what it can; anything else makes the commit refused, with nothing changed, and the refusal lists each path with three commits (fork point, experiment, agent branch). Read them with `knomit_explain {file, commit}` and retry with `resolutions` (`"ours"` = the experiment's version, the opposite of git's `ours`; `"theirs"` = the agent branch's; or `{"body": "<merged text>"}`).
- `rollback` throws the work away. `list` shows the experiments and which one this session is in. `sync` updates the experiment from the agent branch; where both changed a fact, the agent branch's version wins.
- Experiments are local: never pushed, never fetched. One with no commits for the configured expiry is rolled back automatically.
- After reconnecting, `knomit_bind` with `experiment: <name>` resumes it. `knomit_bind` exists only on the unscoped endpoint (`/api/v1/mcp`); on an endpoint scoped to a repo or lens it always fails.

**A one-commit move** without an experiment: `knomit_learn` with `retract` writes the facts and deletes the listed paths in one commit, or does nothing. If any listed path is already gone, the whole call is refused. This is atomic on one branch only: two agents on two branches can each move the same fact. The mission template takes tasks this way.

```json knomit_learn
{"binding": "<handle>", "moment_name": "take",
 "facts": [{"topic": "inbox", "category": "<agent>/working", "title": "…", "body": "…", "type": "signal", "kind": "pragmatic", "expires": "<RFC 3339>"}],
 "retract": ["kb/tasks/<lane>/<id>.md"]}
```
