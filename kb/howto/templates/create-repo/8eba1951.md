# Create a repo from a template: POST /api/v1/repos with mode template and template {repo, name}, kb repo create --template, or the wizard's From a template; the fleet template and a repo on a forge use mode initialize

**1. Find the template.** knomit creates a repo from a template of a mounted repo, so subscribe to `knomit-playbooks` first (`kb/howto/repos/subscribe/`). `GET /api/v1/templates` lists the templates of every mounted repo (`GET /api/v1/repos/{repo}/templates` one repo's) as `{"templates": [{repo, name, description, commit, fact}]}`: `description` is the title of the template's fact and `fact` is its path. To read a template before creating from it, find it with `knomit_query` (`path: "kb/templates/"`, `context: {"part": "template"}`) and explain its template fact. The walk holds its file facts, its edit facts and a `system_file` node per file; explain a node's `path` and `commit` to get the file's raw `content`.

```json knomit_explain
{"binding": "<handle>", "file": ".knomit/templates/<name>/<path>", "commit": "<the node's commit>"}
```

**2. Create the repo from it.** Three routes, one request:

- REST: `POST /api/v1/repos` with mode `template`.
- CLI: `kb repo create <new repo> --template <repo>/<name>`.
- Web UI: the create wizard's ontology step, **From a template**.

```
POST /api/v1/repos
{"name": "my-repo", "mode": "template", "template": {"repo": "knomit-playbooks", "name": "<template>"}}
```

knomit copies the template's root `README.md` and everything under `.knomit/` from `.knomit/templates/<name>/` (read at the source repo's consensus tip) to the same paths in the new repo, in one signed commit with the trailers `Knomit-Template` and `Knomit-Template-Source`. The new repo is an ordinary repo afterwards; nothing links it back to the template except those trailers. The create answers `202` with a `create_id`; `GET /api/v1/repo-creates/<create_id>` reports its progress. A template with any other path in its folder, a symlink or executable file, more than 256 files or 4 MiB, or no valid new ontology at `.knomit/ontology.yaml` is refused before anything is written (422).

**3. Pick the mode by where the repo lives.**

| mode | ontology and files | use it for |
|---|---|---|
| `template` | the template's files; `ontology_preset` and `ontology_yaml` are refused | a new local repo from any template except `fleet` |
| `initialize` | exactly one of `template`, `ontology_preset`, `ontology_yaml`, written onto knomit's agent branch cut from the remote branch's tip; the branch needs a commit and no ontology, its other files stay, the consensus branch is not touched | a template for a repo with a git origin: the `fleet` template, a repo on a forge |
| `custom` | `ontology_yaml`, parsed as a NEW ontology (problems that are only warnings on an existing repo are refused) | your own ontology, no template |
| `preset` | `ontology_preset`: `default` (id `general`), `code` (id `source-code`) or `fleet` (id `fleet`), the copies embedded in the running knomit binary | the built-in presets, no template; never `fleet` (`kb/gotchas/repos/ontology-at-create/`) |
| `clone`, `subscribe` | the remote branch's `.knomit/ontology.yaml`; `template`, `ontology_preset` and `ontology_yaml` are refused | joining or following a remote repo that already holds an ontology (`kb/howto/repos/subscribe/`) |

The `fleet` template is refused in mode `template` (409): create it with `initialize` and join with `knomit fleet register <url>`:

```
POST /api/v1/repos
{"name": "my-fleet", "mode": "initialize", "origin": {"url": "<git URL>", "branch": "main"}, "template": {"repo": "knomit-playbooks", "name": "fleet"}}
```

**4. Follow the template's README** for anything beyond the create (hosting a mission repo, joining a fleet), and make the edits its edit facts (`kb/templates/<name>/use/`) list.

Check an ontology of your own first with `POST /api/v1/ontologies:validate` (the YAML file as the body): it answers `"ok": true` with the id and topics, or the diagnostics. Sharp edges: `kb/gotchas/repos/ontology-at-create/`.
